The source, with real line numbers

Every claim is tied to a line of the deployed ref. Line numbers move between releases, so the ref is always stated.

StatsMapper.xml · upsertDailyStats · CTE time_total · ref origin/prod 
1738time_total AS (/* study time */1739    SELECT log.ENTITY_ID, ROUND(SUM(TIMESTAMPDIFF(SECOND, BEGIN_DT, IFNULL(END_DT, ...))) / 60) AS MINUTES1740    FROM time_log log1741        JOIN access_list sel ON sel.entity_id = log.ENTITY_ID1742    WHERE sel.day = #{inputDay} AND BEGIN_DT < END_DT  ‡       AND log.BEGIN_DT < '2026-08-07'   -- hypothetical, not in production1743    GROUP BY log.ENTITY_ID)
MINUTES for a1b2c3d4, input 2026-08-06 154
  1. ①Line 1739, SUM: where the value is made

    3,000 + 3,083 + 3,140 = 9,223 s ÷ 60 → 154
    IFNULL, ROUND and TIMESTAMPDIFF inside the SUM filter nothing.

  2. ②Line 1742, WHERE: where the range is decided

    sel.day picks which entities are computed. BEGIN_DT < END_DT compares two columns of the same row. No condition compares a date with a value.

  3. ③Line 1741, JOIN: where the input travels

    The input reaches access_list only. Every row in time_log for that entity enters the sum.

One bundle, always in this order

Prose cannot carry a negative like “there is no date cut”. The skill answers with these five parts instead.

  1. 1

    Source with real line numbers

    Extracted from the deployed ref, line breaks and comments intact.

  2. 2

    The real rows those lines read

    One sample entity with five rows or fewer. Ids shown as an 8-character prefix.

  3. 3

    ①②③ arithmetic per line

    Where the value is made, where the range is decided, where the input does and does not travel.

  4. 4

    Results where only the input changes

    The block runs as-is on a read-only environment. Same text, different input.

  5. 5

    An executed counter-example

    Exactly one hypothetical line added to the production SQL and run. Its value sits next to the real one.

154c

extract_block.py

Pulls a MyBatis statement, or one CTE inside it, from any git ref with its original line numbers. Use worktree as the ref to read the file on disk.

python3 scripts/extract_block.py <repo> <git-ref> <mapper.xml> <statement-id> [cte-name] [--scan] [--sql]
FlagOutput
(none)The whole statement, or only the named CTE, each line prefixed with its number in that ref.
--scanOnly the lines that touch dates or ranges: _DT, startDate, NOW(, CURDATE, INTERVAL, BETWEEN, <=, >=. Classify each as selection, state or range.
--sqlRunnable SQL without line numbers. XML comments and CDATA removed, #{param} kept for you to fill in.

Put the counter-example next to the real value.
